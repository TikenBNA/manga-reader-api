# MangaReader API — мультиисточниковый прокси

Собирает каталоги нескольких хентай-сайтов, склеивает одинаковые работы и отдаёт всё
в JSON-контракте читалки. Без зависимостей, Node.js 18+.

## Запуск

```bash
node server.js          # http://localhost:3001
```

Источники поднимаются из `cache/catalog-<id>.json` (если свежее 12 ч), иначе обходятся
в фоне. `/api/sources` показывает прогресс, `/api/manga` до готовности отдаёт `503`.

## Источники

| id | Сайт | Как устроен | Статус |
|----|------|-------------|--------|
| `mm` | multi-manga.com | DLE, 669 стр. каталога | каталог, главы, страницы, теги |
| `moody` | online.hentaimoody.com | DLE + JSON API (`json.imghmd.link`) | каталог, главы (манифест), страницы (`images.json`) |
| `nudemoon` | kpez.nude-moon.pro | пост = читалка `/view/<id>/` | каталог, страницы, теги (`/cat/`) |
| `allhen` | 20.allhen.online | SSR, 30 112 тайтлов, `?offset=` | каталог/серии читаются, **ридер блокирует не-браузер** |
| `hentailib` | hentailib.one | SPA, контент в JS-бандле | API не найден, нужен разбор бандла |

## Эндпоинты

| Путь | Ответ |
|------|-------|
| `GET /api/manga?page=1[&source=nudemoon]` | `[{ id, title, cover, author, genres, sources[] }]` |
| `GET /api/manga?tag=<slug>&page=1` | работы с тегом; несколько параметров `tag` = строгое И |
| `...&sort=old` | сортировка по дате: по умолчанию новые сверху, `old` — старые |
| `GET /api/tags` | `[{ slug, name, sources[] }]` |
| `GET /api/sources` | состояние источников |
| `GET /api/manga/<src:id>` | `{ id, title, cover, author, description, genres, sources }` |
| `GET /api/manga/<src:id>/chapters` | `[{ id, number, title, date }]` |
| `GET /api/chapter/<src:id>/pages` | `{ pages, prevChapterId, nextChapterId }` |
| `GET /demo` | песочница: каталог, фильтр по тегам, читалка |

`id` — с префиксом источника (`mm:16737`, `moody:310452`, `nudemoon:31471`); старые
числовые трактуются как `mm`.

## Дедупликация

1. Источник отдаёт плоский список постов.
2. Название нормализуется в `workKey`: регистр, `ё→е`, вырезаются переводы в скобках,
   пунктуация, хвосты «- глава N», «№N».
3. Посты с одинаковым ключом = одна работа; на каждый источник остаётся один адрес
   (`sources: [{ source, id, url }]`).
4. Теги — `tagKey` (`Big Tits` = `big tits` = `big-tits`), дубли схлопываются,
   у тега список `sources` со своими slug'ами.

Текущее состояние: **17 995 уникальных работ**, **214 тегов**, 224 работы встречаются
более чем на одном сайте.

## Ограничения

1. У `nudemoon` пост — сразу глава, поэтому у работы одна глава (номер вытаскивается из «№N»).
2. `allhen`: каталог (`/list/category/manga?sortType=POPULARITY&offset=50`, 50 на страницу)
   и страницы серий парсятся, но страницы чтения отдают RST для не-браузерных клиентов —
   нужен headless-браузер или их API.
3. `hentailib`: контент рендерится из JS-бандла, XHR-каталога не видно — нужен разбор бандла
   или скрин Network из браузера.
4. Теги есть только у `mm` и `nudemoon`; у `moody` жанры берутся со страницы тайтла и в
   общий список тегов пока не попадают.
5. Обход каталогов — сотни запросов; на хостинге нужен планировщик и rate limit.
6. `description` чаще всего пустой, `author` заполнен не везде.

## Проверка на телефоне

Сервер слушает все интерфейсы, поэтому с телефона в той же сети:

```
http://<IP-компьютера>:3001/demo
```

IP: `ipconfig` → IPv4 основного адаптера. Firewall: правило для `node.exe` должно разрешать
входящие (Private/Public). Демо адаптировано под телефон: две колонки, липкая шапка, фильтры
в отдельной строке, читалка с тап-зонами по краям и свайпами, `env(safe-area-inset-*)` под вырезы.
Ответы API и HTML отдаются gzip, каталог кэшируется на клиенте.

## Деплой

Сервер долгоживущий (фоновый обход каталога + кэш в памяти), поэтому serverless не подходит.
Готовы Dockerfile, `render.yaml` и `fly.toml`; `GET /health` отдаёт состояние источников.

**1. Render** — самый простой путь: New → Blueprint → выбрать репозиторий, Render сам прочитает
`render.yaml` (Docker, healthcheck `/health`, диск `/app/cache` под кэш каталога).
Бесплатный план засыпает через 15 минут простоя — первый запрос после сна снова обходит каталог
(2–4 минуты), поэтому лучше платный Starter.

**2. Fly.io** — `fly launch --copy-config` (подхватит `fly.toml`) → `fly deploy`.
Volume `catalog_cache` монтируется в `/app/cache`, поэтому каталог переживает перезапуски.

**3. VPS (Timeweb/Beget/Hetzner)** — `docker build -t manga-api . && docker run -d -p 3001:3001 -v C:\Users\User\Documents\deepseek-harness\default-workspace/cache:/app/cache manga-api`,
сверху nginx + сертификат (Caddy проще: одна строка в Caddyfile).

**4. Быстро показать наружу без хостинга** — Cloudflare Tunnel с домашнего компьютера:

```
cloudflared tunnel --url http://localhost:3001
```

Выдаёт публичный `https://*.trycloudflare.com` без аккаунта; живёт, пока запущен процесс.

Переменные для продакшена: `PORT` (даёт платформа), `MM_MAX_PAGES` (сколько страниц каталога
обходить при старте), `MM_CATALOG_TTL` (время жизни кэша), `MM_CRAWL_CONCURRENCY` (1–3 на
слабом CPU).

Фильтр по тегам в демо: кнопка «Теги» открывает список с поиском, теги можно отмечать несколько,
выбранные показываются пилюлями с «✕» и кнопкой «Сбросить всё». Состояние фильтра живёт в URL
(`?tags=ahegao,без-цензуры&source=mm`), поэтому ссылку можно переслать или обновить страницу —
фильтр сохранится. Несколько тегов дают строгое И: работа должна быть на странице каждого тега.

## Теги: откуда берутся и почему их «меньше»

Список тегов складывается из трёх источников:

1. `/tags_pages.xml` сайта — 188 тегов, но он устаревший (последнее обновление 2023);
2. теги, встреченные при разборе карточек постов — с настоящими slug'ами (`/tags/<slug>/`),
   пополняются при каждом открытии работы и при фоновом прогреве (`MM_TAG_WARM`, по умолчанию 200 работ на старт);
3. список `/tags/` у nudemoon — 60 тегов.

Всё это пишется в `cache/tags.json` и переживает перезапуск. При слиянии теги канонизируются
(регистр, ё, пунктуация), поэтому 222 записи дают 217 уникальных тегов: дубли между сайтами
схлопываются, а не исчезают.

Если тега нет в списке — значит он ещё не встретился ни в sitemap, ни в разобранных постах.
Лечится либо бо́льшим `MM_TAG_WARM`, либо просто открытием работы с этим тегом.

## Навигация в демо

- Каталог **не пересоздаётся** при переходе в мангу: DOM списка и `scrollY` запоминаются,
  поэтому «← Каталог» возвращает туда же, где ты был (включая догруженные страницы и фильтры).
- Сортировка: `Новые` (по умолчанию) и `Старые` — по дате выхода. В API это `?sort=old`.
  Порядок строится по позициям в каталогах источников (они отдают новые сверху), поэтому
  сортировка работает без разбора даты у всех 18 тысяч работ; дата подставляется при открытии карточки.

## Объединённые главы и источники

- Список глав собирается **со всех источников**, где есть работа: mm отдаёт главы отдельными
  постами, moody — томом с несколькими главами, и они склеиваются по номеру главы.
  В каждой главе есть поле source, поэтому листание 
ext/prev идёт сквозь источники
  (mm:16711 → moody:310451).
- Название хвостов нумерации (- глава 4, Том - 1 Глава - 4, часть 2) отрезается одним
  правилом stripChapterSuffix, поэтому работы с разных сайтов сходятся в одну.
- Фильтр по источнику **уберан из интерфейса** — по умолчанию показываются все источники.
  В API параметр ?source= остался, если понадобится для отладки.
